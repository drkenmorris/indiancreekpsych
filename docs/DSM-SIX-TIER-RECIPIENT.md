# Six-tier adult recipient workflow

New adult assignments use `icps-dsm-recipient/2` and pin the original Tier 1 profile plus the evidence, differential and clarification manifests. Tier 1 routes domains using the existing current/past-concern rule. Each selected adult domain receives its Tier 2 evidence/context items and the complete original Tier 3, 4, 5 and 6 question banks. This recipient version asks the full bank for selected domains; the clinician's existing engine still interprets candidate follow-ups according to its original branching rules. All submitted answers, including additional candidate responses, remain visible in the original administration response view. Unknown/private answers are preserved; no diagnostic exclusion or probability is introduced.

Tier 6 also accepts optional onset/event dates and up to 2,000 characters each of examples and context. Unknown dates can be left blank; impossible/future dates are rejected by both API and SQL. The form saves between seven-item pages, can pause/resume, and requires explicit confirmation before final submission. Direct database writes enforce source choices, domain selection, required answers, sequential pages, immutable submitted data and optimistic revisions.

The existing verified email/MFA recipient gate and assigning administrator ownership remain in force. A therapist must have an authorized clinic administrator account; this release does not create a new therapist role or grant access to another clinician's records. Paubox dispatch remains behind the existing configured delivery/BAA/release controls. No invitation is sent by deployment or draft creation.

Existing `/1` assignments are never silently upgraded. Their original source and responses remain supported. Create a new adult assignment for six-tier delivery. Adolescent and caregiver assignments retain their clearly labeled Tier 1 scope; no adult differential questions are substituted for children. This release integrates the developed six-tier adult instrument; it does not create deeper youth instruments or establish clinical validity.

## Supabase and previous administrations

`psych_test_assignments` binds each independent administration to the immutable central patient UUID, intended recipient and source snapshot/hash. `dsm_assignment_responses` retains current progress/submission and `dsm_assignment_response_versions` retains every saved answer revision. `dsm_records.source_assignment_id` links one independent clinician working assessment to that submission; `dsm_record_versions` retains the clinician's append-only state/report/provenance history. Original respondent answers remain immutable when the clinician edits a working assessment.

The patient's `/emr/dsm?patient=UUID` view lists every assigning clinician-owned administration by date, submission state and answer count, with original responses and linked clinician evaluations. Independent clinician assessments are also listed. The clinician can open the original imported evaluation, the latest evaluation, and the existing read-only revision history. Creating another administration never replaces earlier ones. Source-less historical drafts require recreation, while valid earlier recipient sources remain readable.

Tests cover all 19 adult domains through six tiers, canonical report reconstruction, optional fields/dates, older source compatibility, two independent administrations for one patient, inaccessible unrelated-account records, and actual history-page links. Software verification uses fictional records and is distinct from psychometric validation or inbox delivery confirmation.
