# Clinical-development and validation plan

This plan is not a claim that clinical validation has occurred. Synthetic routing tests verify software behavior only.

1. Freeze a reviewable version. Clinicians inspect the complete original question bank, every response format, routing/reconciliation rule, omitted diagnostic areas, cultural/developmental assumptions, and safety handling. Record reviewer decisions against immutable question/rule versions.
2. Review permissions before importing or adapting any published diagnostic criteria, structured interview, scoring system or copyrighted questionnaire. The current original content is not an official APA DSM instrument.
3. Perform cognitive interviewing and usability evaluation with appropriate consent and governance. Check comprehension, ambiguity, accessibility, response burden, distress, completion/abandonment, and how respondents use Unsure/Private/unknown dates. Develop youth versions independently.
4. Establish an appropriate, legally usable reference assessment performed by qualified clinicians. Use independent/blinded review where feasible and preserve disagreements rather than forcing a single answer. Do not use this prototype's own outputs as the reference diagnosis.
5. Evaluate representative clinical populations, multiple conditions and co-occurrence, common alternatives and medical/substance explanations. Report domain-specific sensitivity/specificity, predictive values at stated prevalence, calibration only if probabilities are developed, missing-data behavior, subgroup performance, and confidence intervals. Determine sample sizes and acceptance limits prospectively with clinical/statistical expertise.
6. Separate development and held-out validation data. Do not tune rules on the held-out results. Version all changes and evaluate their effects. Assess reliability and follow-up performance where relevant. Synthetic examples cannot establish clinical accuracy.
7. Evaluate clinically important misses and inappropriate escalation, response to ongoing threat or uncertain safety information, human review burden, and whether reports help clinicians make better decisions. Completing a questionnaire never establishes safety or a diagnosis.
8. Before any real-patient release, separately implement and verify the owner-deferred authenticated patient/provider mapping, private persistent storage, role boundaries, audit/history, operational response procedures and required agreements. Clinical, legal, privacy and operational review are distinct from a passing software build.

No participant recruitment, real-response collection, paid licensing, clinical integration or new external data transfer is authorized by this document.
