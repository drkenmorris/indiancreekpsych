# Connected EMR workflow release

Owner requested publishing the EMR already built and authorized the shared Indian Creek account/patient repository. The new `/emr/workspace?patient=UUID` entry reuses the existing original menus/forms and Python validation engine. It uses the clinic session, verified administrator role and MFA. The selected central UUID remains authoritative. No browser-carried demo charts, credentials or sample patients are imported.

The connected legacy forms use a protected Node session bridge and a Python function. The Python function independently validates the exact bearer token with Supabase Auth, checks MFA and the current profile role, then reads/writes with that caller's RLS privileges. Neither browser-supplied state nor client-supplied owner IDs are accepted. The bridge forwards tokens only to the configured clinic deployment, never to a caller-controlled host. No service-role key is used.

`emr_workspaces` stores each administrator's current patient-bound workflow state. `emr_workspace_versions` retains saved revisions. Clinical rows append; older entries cannot be removed/changed. Optimistic revisions reject competing saves. Reviewed demographics update the central patient row atomically, preserving demographic history and detecting central-page conflicts. Existing DSM assessments remain in their dedicated revisioned tables under the same patient UUID. No frontend response storage is used. Display preferences/custom field definitions remain browser settings.

Modules include the existing Personal Data/insurance, biopsychosocial histories, assessment/problem-library, treatment-plan, notes, prognosis, discharge, reports and record-history forms. Patient selection/addition goes through the central directory. Central records without reviewed DOB can be viewed; completing the legacy demographics form still requires a valid birth date. Provider identity/security uses existing clinic account management; old browser-provider registration is not migrated. Additional provider/care-team access needs explicit clinic permissions and is not automatically granted by this release.

Shared group records are unavailable pending central participant/care-team permissions. Appointment Scheduler links to the existing clinic scheduler; the synthetic availability engine is not presented as live. Claim previews remain previews with no claims submission or eligibility verification. Existing demonstration signature workflows are not valid clinical electronic signatures. Original questionnaires/libraries and legal document tools retain their developmental/verification limits. Copied template text may still identify a record or instrument as synthetic; this is retained provenance, not a statement that real clinical validation has occurred. Fictional intake autofill helper panels are removed. Automatic patient-intake field transfer into every EMR section is separate work.

Saved clinical form snapshots are private to their creating MFA administrator, using the same patient registry. Other therapists do not gain access from a role label or patient name. Explicit account reconciliation for an unregistered EMR patient later registering a portal account remains pending. No patient responses are copied during release.

Verification: Python adapter tests cover save/reopen, central-only bootstrap, invalid input, cross-patient rejection, stale writes and disabled external actions; database tests cover RLS/MFA, owner isolation, immutable history, chart separation and atomic demographics. Existing intake/DSM checks and production build remain required. Final production and authenticated fictional browser evidence are recorded in the workspace release report.
