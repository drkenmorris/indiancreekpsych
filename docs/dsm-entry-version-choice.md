# DSM questionnaire version choice at intake and assignment entry

Optional DSM version selection appears at the end of current patient and office-assisted intake, after the last legal form/PDF section. It remains separate from legal statements and signed PDF fields; page count/order and legal packet revision remain unchanged. Existing historical submissions without this optional field do not show a new patient-facing question. Selected values are read-only after submission and are labeled in staff review. Normal intake draft/submission storage carries only selection metadata under dsm_questionnaire_version; no DSM symptom responses are added.

The same three choices appear when DSM is selected on the existing administrator/provider assignment screen: adult self-report18+, adolescent self-report11–17, parent/guardian observations for child6–17. DSM drafts require an explicit version; other tests omit the selector and store null. Returning to another test clears a stale DSM selection. The selected value saves in psych_test_assignments.dsm_version, displays in the assignment list and on the protected recipient assignment page. Older assignments remain unchanged with null and display Version not selected; a new draft is needed to choose a version. Saved assignment identity/version remains immutable.

Client/API/database validate the three allowed values and age compatibility against the patient's DOB using America/Chicago calendar date. Intake drafts may leave the choice or DOB blank; an entered DOB must fit the selected version. The new private insert trigger checks DSM assignment selection without changing RLS or granting helper privileges. Existing private intake validator is extended only by the optional whitelist key and the version/age checks; deployment preflight verified the baseline function source hash before replacement. Non-DSM assignments cannot carry DSM metadata. Existing auth/MFA, owner scope, submitted-record immutability and email release gates remain intact.

This prepares the version decision for the eventual questionnaire launch. It does not make unvalidated DSM forms patient-ready, enable invitations, create guardian account access, grant therapist roles or save screening answers to the EMR. Current DSM prototypes remain administrator-only. Youth Tier2 content remains pending. A caregiver form selection is not proof of guardianship, permission to access another person's answers or clinical consent.

Tests cover patient and office-assisted save/reload, assignment request/list display, age boundaries and invalid choices, all three database version values, legacy null retention, immutable assignment version, current owner/MFA/patient role restrictions, unchanged other intake validation and no invitation sending. No real patient records or invitations are used in verification.
