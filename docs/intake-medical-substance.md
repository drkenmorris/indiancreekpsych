# Aligned medical / substance-use history

Patient intake page 7 and the EMR medical/substance-use page use the same original version 2.1.0 definition: eight groups, 112 choices, five clinical details/source fields plus primary-care provider, primary-care phone, non-medication allergies and gambling/other compulsive-behavior details. The definition JSON is identical in both source snapshots. None reported / History unknown are exclusive within their own group; blank means unassessed. Multiple selections may describe different conditions/substances/time periods, so details identify these associations. No scoring, diagnosis, coverage or clinical verification is inferred.

Page 7 now has one optional structured form instead of 13 overlapping legacy text inputs. Medical care and neurological events are represented once in the appropriate groups/details. Pregnancy/reproductive concerns are one existing medical-condition choice with optional detail. Medication lists and medication allergies remain on page 6. Older page-7 answers remain stored and appear as read-only previously recorded answers in patient/kiosk/staff views; no unbounded text is truncated and no text is classified into checkbox selections. Staff review uses the same readable summary. The prior page-5 field removals remain intact.

medical_substance_history is a JSON-encoded string in the existing answer map: definition_version, selections and notes. Server validation enforces known version, shape, group/choice membership, no duplicates, exclusive controls, nine known bounded string details (4000 characters each), 50000-character packet limit and the existing 160000-byte answer limit. Old answer keys remain accepted; medical_conditions is no longer separately required. Patient/kiosk roles/MFA/RLS, stale-save comparison and submitted locks are unchanged. No real answers were read for implementation.

The EMR retains old immutable definition snapshots. New snapshots use 2.1.0 and include the four additional details. Its explicitly fictional intake demonstration reuses the editor fields and copies selected groups/nonblank notes into the chosen demo chart's draft. Conflicts require confirmation, unanswered groups/blank details preserve existing draft values, and explicit None/Unknown replace a group consistently. Standard Save retains an append-only snapshot. This does not connect clinic submissions or accounts to the browser-carried EMR demo.
